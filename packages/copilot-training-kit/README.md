# Learn GitHub Copilot in VS Code

GitHub Copilot in Visual Studio Code (VS Code) works on the files on your computer. You ask in plain
words, and it reads your documents, writes new files and runs commands. It asks you before it runs a
command that could change something. You can undo the edits it makes to your files.

These trainings teach you to direct it. You don't need to write code. Start with Getting started;
each training builds on the one before it.

## The trainings

- [Getting started](getting-started/README.md): make your first request, change Copilot's work and undo it, have it explain code, and give it instructions for a folder.
- [Skills](skills-in-depth/README.md): save your instructions for a task you repeat, so Copilot follows them when you ask for that task.
- [Custom agents](agents/README.md): set Copilot up for one role, such as reviewer or planner, with its own instructions and tools.
- [Connecting your tools](connecting/README.md): connect Copilot to another service, such as GitHub, so Copilot can get information from that service.

## Which to use when

Most of the time, you just ask. When you keep repeating yourself, or Copilot needs something it
doesn't have, you can set Copilot up ahead of time. Find your case below, and try the smallest option
that covers it.

| When this happens | Use | Taught in |
|---|---|---|
| You need something just this once | Just the request | Getting started |
| You give the same rules in every request in a folder | Custom instructions | Getting started |
| You explain a task, such as a weekly summary, step by step every time | A skill | Skills |
| You describe the same role, such as reviewer or planner, chat after chat | A custom agent | Custom agents |
| Copilot needs information from another service, such as GitHub | A connection | Connecting your tools |

Often more than one would work, and one job can use several. VS Code has other ways to set
Copilot up, such as hooks and prompt files. These trainings don't cover them.
