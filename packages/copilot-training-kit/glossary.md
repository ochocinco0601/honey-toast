# Glossary

| Word | Meaning here |
|---|---|
| VS Code | Visual Studio Code, the program the training runs in. A folder open in it is your workspace |
| Copilot | GitHub Copilot, the assistant inside VS Code that this training is about. Not the assistant in your office suite |
| Workbench | This training's word for VS Code with a folder open: a table you lay work out on and leave it there between sittings, where the assistant can read the files and act on them |
| Workspace | The folder, or folders, currently open. The assistant reads and writes inside them. With two folders open, VS Code offers to save the set under a name so you can reopen both at once |
| The list on the left | The panel showing the open folder's files and folders. VS Code calls it Explorer. If it is missing: menu View, then Explorer |
| Chat | The panel where you talk to the assistant |
| Agent mode | The chat setting in which the assistant can act, not only answer. Chosen with the small selector at the bottom of the chat box |
| Permission prompt | The button inside a reply that asks whether the assistant may run a command on your machine, until you allow commands for the session |
| Chore | One piece of file work from start to finish: organize a folder, summarize a set of notes, analyze one export |
| Check the receipts | Ask the assistant which files its answer came from, open one, and see whether it says that. An answer with no source is a guess |
| House rules | Your team's standards written once in an instructions file in the folder, so the assistant follows them without being told each time |
| Skill | A text file of instructions that tells the assistant how to do a particular job your way |
| Extension | An add-on installed from a marketplace, like an app on a phone |
| CSV | A plain-text spreadsheet export, and the safe format for the assistant to read. Most systems that export to a spreadsheet can produce one |
| Repository | An application's source code and supporting files, kept in a shared system |
| Code host | The shared system where repositories live, with their history and reviews. GitHub is one |
| Git | The version-control program that copies a repository to your machine and tracks changes to it. The assistant runs it for you |
| Clone | Make a local copy of a repository |
| Commit, pull request, merge | The steps by which a change is proposed, reviewed and accepted into the shared copy |
| Markdown | A plain-text format for documents. Raw, it shows # and * symbols; previewed, it reads like a page |
| Preview | The readable rendering of a markdown file. Ctrl+Shift+V opens it |
| Connector | A configured link that lets the assistant read a system directly instead of an export |
