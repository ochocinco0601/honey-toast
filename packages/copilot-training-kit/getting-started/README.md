# Getting started with GitHub Copilot in VS Code

In this training you hand real file work to GitHub Copilot, the assistant inside Visual Studio Code
(VS Code), and check what it did against the files. If your work arrives as files, such as ticket
and change exports, notes, spreadsheets, a folder someone sent you, or an application you support,
it is for you. You do not need to write code.

This is the first training in a series, for beginners. More advanced trainings follow it; see
[all the trainings](../README.md).

## What you will be able to do

- Open a folder in VS Code and have the assistant make something in it, allowing only what you asked for.
- Have it read a folder of your own work and write something from it, then check that against the files.
- Get a plain account of an application you do not own, with one claim checked in its files.
- Write a request of your own and use it on a real piece of your work.

You need a Windows computer with VS Code and a GitHub Copilot licence; see
[Before you start](#before-you-start).

## The path

1. [Start here](start-here.md): about fifteen minutes. You end
   with a folder the assistant made on your computer, and a check you did yourself.
2. [Lesson: your own files](lesson-your-files.md): about thirty minutes. You end with a file the
   assistant wrote from your own work, checked, and a request you wrote yourself.
3. [Lesson: an application you do not own](lesson-application.md): about twenty-five minutes, plus
   two steps later. You need an application's address. You end with a plain account of what the
   application does, with one claim checked in its files.
4. [Your first real chore this week](first-real-chore.md): on your own work.

In the list of files in VS Code or on GitHub, the pages are in alphabetical order; follow the
order above instead.

## How this training works

- **You do it yourself, at your own pace.** No instructor is needed, whether or not you went to a
  session. The path below takes about an hour and a quarter, in sittings as short as you like.
- **The assistant is your helper.** It lives in VS Code, which you open in the first step of Start here; keep it beside
  these pages. You type or paste every request yourself, because operating it is the skill you are
  learning. When you are stuck on a step, a message or a word, ask it:
  [When you are stuck](../troubleshooting.md#when-you-are-stuck-ask-the-assistant-first).
- **You check what it gives you** against the files, with your own eyes, before you use it.

It is not the Copilot in your office suite; [why this one is different](../explanation.md).

## Before you start

- A Windows computer with VS Code installed, and the assistant signed in with a licence. If it is
  not, see [Getting set up](../troubleshooting.md#getting-set-up).
  `[YOUR ORGANIZATION: who to ask when setup fails]` If there is no one named here, ask whoever sent you this training.
- **Which files you may use.** Until your organization tells you otherwise, use only files with no
  customer names, account numbers, personal details, passwords or system addresses. Most ticket
  and change exports have some of these: delete those columns first, or use a copy with made-up
  values. Not sure a file counts? Use the practice files in this training's `sample-files` folder,
  until you can ask.
  `[YOUR ORGANIZATION: which classes of data may be used with the assistant]`
- A box that says YOUR ORGANIZATION marks an answer your organization supplies. If one still shows
  its bracketed description and there is no one to ask, follow the rule beside it and carry on.
  Only three can stop you: getting VS Code and the assistant set up, your licence, and access to an
  application's code.
- These pages were checked against VS Code `[YOUR ORGANIZATION: version]`. If a button or menu has
  a different name on your screen, your screen is right; ask the assistant where it went.
