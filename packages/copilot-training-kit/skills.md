# Skills: what they are, how to use one, where ours are

For someone who has finished README.md. This page is a reference, not a lesson: come to it when
you want to use a skill someone else made, find the ones your organization provides, or share
one of your own.

## What a skill is

A skill is a text file of instructions that tells the assistant how to do one job your way: how
your team writes a status summary, how to analyze a set of tickets, how to document an
application. The assistant already knows how such jobs are generally done. The skill says how
they are done here. You can open a skill and read it; it is only text.

## How to use a skill someone else made

Two ways, either works:

- Ask for it by name in plain words, and name the file it should work on:
  > Use the ticket-commonality skill on `export.csv` in `<your folder>`.
- Type a forward slash in the chat box and start typing the skill's name. A list appears; pick
  from it.

To see which skills are available to you right now, type a forward slash and read the list, or
ask:

> What skills are available in this setup, and what does each one do?

**Check:** a skill's result should name the file it worked on. If it does not, or the result is
not what the skill's description promised, say so and ask it to redo the job.

## Which skills to expect

Skills follow the work people already do. Across an operations organization the same jobs recur
on every team: reading incident and change exports, preparing a monthly review, documenting an
application, analyzing failure modes, checking a runbook. Where your organization has a shared
skill for one of these, use it rather than writing your own, so teams get the same answer the
same way.

## Is it safe to download a skill?

A skill is text. Read it before you use it, as you would any file someone sent you. Downloading
from outside the organization may be restricted; see `faq.md`. Skills published inside your
organization have already been through whatever review it applies.
