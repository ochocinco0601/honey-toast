## Alert M300: Checkouts that ended with no order

### What fired

**M300 Checkouts that ended with no order** is above the operators' threshold for longer than their window ([ALERT.md](ALERT.md)).

**The expectation it guards:** a checkout that reaches Ordering API and writes no order leaves the customer with no order and, on the web front end, an emptied basket and the orders page, so the customer is not told (lifecycle L01, recovery not created; WebApp/Services/BasketState.cs:107-108; WebApp/Components/Pages/Checkout/Checkout.razor:111-116). A checkout that never reaches Ordering API fails in front of the customer and is not counted here; nor is an order call refused at authentication, which writes no command line (Ordering API's answers by status show it)

- Leaving by L01 (The order is placed): M300 counts those cases

**Its cases:** those that left by L01 from `the case is created` in the alert's window. A case still in the stage is not one of M300's.

**Window:** from when the earliest of its cases entered the stage, to now: what sent a case out wrongly can come before it left.

Check the triggers to escalate or declare an incident ([S8](#s8-escalate-or-declare)) at every step, not only at the end.

### S2. What is at stake

- **Order id ("Id")**: The only key that joins the order across services and to the customer
- **Order total (sum of Units x UnitPrice)**: Money the customer pays; value blocked while the order is stuck
- **Items and units (ordering."orderItems")**: What must be in stock and shipped
- **Buyer (ordering.buyers "IdentityGuid")**: Who is waiting and who is told
- **Delivery address**: Where the goods must arrive
- **Payment method (card number masked to the last four digits)**: What is charged
- Customer experience and trust, if “The order is placed” fails: counted in checkouts that emptied the basket and created no order. Ordering API answers 200 even when the order was not written (Ordering.API/Apis/OrdersApi.cs:155-166), and the WebApp empties the basket without reading the answer (WebApp/Services/OrderingService.cs:12-18; WebApp/Services/BasketState.cs:107-108).
- Customer experience and trust, if “The customer's basket is emptied” fails: counted in baskets still holding items already ordered. Both deletes failed; the customer may order the items twice (WebApp/Services/BasketState.cs:107-108; Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:14).
- **Declare an incident** when the impact threshold in the severity definition is crossed: an operator value, linked here.
